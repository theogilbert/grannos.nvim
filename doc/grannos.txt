INTRODUCTION                                                   *grannos-intro*

grannos.nvim is a database client for Neovim. It delegates all database
connectivity to an external server process, communicating with it over
newline-delimited JSON on stdio (the grannos protocol).

Any server that implements the protocol can be used. grannos-py is the
reference implementation: https://github.com/theogilbert/grannos-py

Connection parameters are stored in a JSON file on disk (not in the nvim
config), so they persist across sessions and are shared between any client
that speaks the grannos protocol.

================================================================================
REQUIREMENTS                                            *grannos-requirements*

- Neovim 0.9 or later
- A server that implements the grannos protocol, on $PATH or configured
  via |grannos-server_cmd|. See your server's documentation for
  installation instructions and supported drivers.

SETUP                                                         *grannos-setup*

Call `require("grannos").setup()` once in your config: >lua
  require("grannos").setup()
<
All options are optional. See |grannos-config| for the full reference.

CONNECTIONS PANEL                                        *grannos-connections*

Open the connections panel with |:DbConnections|. Connections are grouped by
driver and persist across sessions. A "Connected to name (driver)" label
appears at the bottom of any window whose buffer has an associated connection.

CONNECTIONS FILE ~

The default location is: >
  $XDG_CONFIG_HOME/grannos/connections.json
  (~/.config/grannos/connections.json on most systems)
<
The directory and file are created automatically when you save your first
connection. You can edit the file directly, or use the panel keymaps below.

WRITE PROTECTION ~                                  *grannos-write-protection*

For SQL and Cypher buffers, grannos uses treesitter to detect write
operations (DML and DDL statements) before dispatching a query. When a write
is detected and the connection has not been permanently allowed, a prompt
offers three choices:

  Abort               Cancel the execution.
  Execute             Run this time; keep prompting on future writes.
  Always allow writes Run and permanently disable the prompt for this
                      connection.

Choosing "Always allow writes" sets `allow_writes: true` in the connections
file for that connection, taking effect immediately and persisting across
sessions.

This flag can also be changed via the edit-connection wizard (`e` in the
connections panel). The wizard includes an "Always allow write operations?"
step that shows the current value and lets you toggle it.

Note: detection relies on treesitter parsers. Buffers without a treesitter
parser (e.g. MongoDB query buffers) are always executed without a prompt.

PANEL KEYMAPS ~

  <CR>    Expand/collapse a driver group, or connect to the database under
          the cursor.
  n       Run the new-connection wizard.
  G       Create a new named group for a driver.
  e       Edit the connection under the cursor (rename and update fields).
  c       Clone the connection under the cursor (prompts for a new name,
          pre-fills all fields from the original).
  D       Delete the saved connection under the cursor (prompts for
          confirmation). On a group row, deletes the group and all its
          connections.
  d       Disconnect from the database under the cursor.
  x       Open the explorer for the connected database under the cursor.
  l       Open the saved-queries picker for the connection or group under
          the cursor. Works on both connection and subgroup entries.
  b       Jump to the buffer associated with this connection. If multiple
          buffers are associated, shows a picker. Focuses an existing
          window already showing that buffer; otherwise reuses any normal
          editing window, or opens a new one to the left of the panel.
  ?       Open driver documentation in a floating window. Works on both a
          driver header and an individual connection entry. Press q or
          <Esc> to close.
  K       Show connection details or error in a hover float. Press K again
          to enter the float (then q or <Esc> to close it).
  R       Refresh the panel.
  q       Close the panel.
  g?      Show a keymap reference float.

STATUS INDICATORS ~

  ✓   Connected (green highlight)
  ✗   Last connection attempt failed (red) — press K for details
  ⠋…  Connecting in progress (animated spinner)

COMMANDS                                                    *grannos-commands*

                                                           *:DbConnections*
:DbConnections
    Toggle the connections panel sidebar.

                                                             *:DbAssociate*
:DbAssociate
    Open a picker listing all currently open connections. Selecting one
    associates the current buffer with that connection. The buffer can then
    be used to execute queries.

                                                               *:DbAttach*
:DbAttach
    Open a picker listing all saved connections. Selecting
    "[+ New connection]" launches the new-connection wizard.
    Tab-completion is available.

:DbAttach {name}
    Connect directly to the named connection without showing the picker.

                                                        *:DbNewConnection*
:DbNewConnection
    Run the new-connection wizard directly. On completion the connection
    is saved and immediately used.

                                                     *:DbDeleteConnection*
:DbDeleteConnection {name}
    Remove the named connection from the connections file.
    Tab-completion is available.

                                                           *:DbDisconnect*
:DbDisconnect [{name}]
    Disconnect the named connection. If {name} is omitted, disconnects
    the connection associated with the current buffer.

                                                             *:DbExecute*
:[range]DbExecute
    Execute lines in {range} (joined with newlines) against the current
    buffer's connection and display the results.

    Examples: >
      :DbExecute          " current line
      :'<,'>DbExecute     " visual selection
      :%DbExecute         " whole buffer
<
                                                           *:DbSaveQuery*
:[range]DbSaveQuery
    Save the text in {range} as a named query. If no range is given, the
    current line is used; a visual selection passes `'<,'>` automatically.

    A floating window shows a preview of the query text. You are then
    prompted for:
      - A name (short label for the query).
      - A scope: Driver, Group, or Connection. When the current buffer has
        an associated connection the options map to that connection's
        hierarchy. Otherwise you are walked through picking a driver,
        group, and connection from your saved connections.

    Duplicate names within the same scope are rejected with a warning and
    you are re-prompted. On success a notification confirms the name and
    scope. See |grannos-saved-queries| for storage details.

                                                          *:DbLoadQueries*
:DbLoadQueries
    Open the saved-queries picker for the connection associated with the
    current buffer. Requires the buffer to have an associated connection
    (run |:DbAssociate| first if needed). Equivalent to `l` in the
    connections panel. See |grannos-saved-queries|.

                                                           *:DbQueryLog*
:DbQueryLog
    Open the query log for the connection associated with the current buffer.
    See |grannos-query-log|.

                                                         *:DbCancelQuery*
:DbCancelQuery
    Cancel the in-flight query whose gutter running icon sits on the cursor
    line. Sends a `cancel` request to the server for that request's id; the
    query receives an error response with "cancelled". If the cursor is not
    on a line with a running-query icon a warning is shown.

                                                             *:DbExplore*
:DbExplore
    Open the schema explorer sidebar for the connection associated with
    the current buffer (falls back to any open connection).
    See |grannos-explorer|.

                                                                *:DbStop*
:DbStop
    Kill the server process and clear all session state.

                                                             *:DbRestart*
:DbRestart
    Restart the server process. Equivalent to |:DbStop| followed by
    starting the server again. All state (open connections, buffer
    associations) is cleared.

                                                     *:checkhealth-grannos*
:checkhealth grannos
    Verify the installation: that |grannos-server_cmd| points at a server
    that starts and answers `capabilities` with a compatible protocol
    version, and that everything else the plugin needs is in place.
    See |grannos-health|.

QUERY LOG                                               *grannos-query-log*

|:DbQueryLog| opens a floating four-panel UI showing all queries executed on
the current buffer's connection during this session.

LAYOUT ~

  Left top     Search input — type to filter the list in real time.
  Left bottom  Filtered list of past queries. Each row shows:
               - Status indicator (see below)
               - Timestamp (HH:MM:SS)
               - Source line number
               - Truncated SQL text
  Right top    Full SQL of the highlighted list entry.
  Right bottom Result of the highlighted entry: row table (up to 50 rows),
               row/affected count, or error message.

KEYMAPS ~

  (type)       Filter the list in real time from the search input.
  <CR>         In search: move focus to the list.
               In list: close the log, jump to the source line in the
               originating buffer, and restore the result in the results
               window.
  <Esc>        In search: clear the filter (or close if already empty).
               In list: close the log.
  /            From the list: return to the search input (insert mode).
  q            Close the log.

STATUS INDICATORS ~

  (none)  Query completed successfully.
  ✗       Query failed — highlighted in red.
  …       Query is still running.

SAVED QUERIES                                          *grannos-saved-queries*

Use |:DbSaveQuery| to store a query with a name and a scope.

SCOPES ~

A scope determines which connections a query is visible to:

  Driver      — any connection that uses the same driver (e.g. all SQLite
                databases).
  Group       — all connections inside a named group for that driver.
  Connection  — a single specific connection.

When listing saved queries, results from all three levels are merged with
more-specific entries taking precedence over broader ones.

LISTING SAVED QUERIES ~

Run |:DbLoadQueries| from any buffer that has an associated connection, or
press `l` on a connection or group entry in the connections panel.

A picker opens (fzf-lua if installed, `vim.ui.select` otherwise) listing all
queries in scope for that connection — connection-specific entries first, then
group-level, then driver-level. Duplicates are removed (more-specific wins).
In the fzf-lua picker you can search by both name and content simultaneously.

  <CR>    Open the query in a new buffer (see QUERY BUFFER below).
  <C-d>   Delete the highlighted query (prompts for confirmation).

QUERY BUFFER ~

A query opened from the picker gets a dedicated buffer:
  - Name: `grannos://queries/<scope>/<query_name>`
  - `buftype=nofile`, editable (`modifiable=true`)
  - A comment at the top of the buffer notes that edits do not update the
    saved query file on disk.
  - `filetype` matches the extension used when the query was saved
  - Automatically associated with the connection the picker was launched from,
    so |:DbExecute| keymaps work immediately
  - Opens in a new split each time; listed in |:ls|

STORAGE ~

Queries are stored as plain text files under: >
  $XDG_DATA_HOME/grannos/queries/
  (~/.local/share/grannos/queries/ on most systems)
<
The directory tree mirrors the scope hierarchy: >
  driver/<server>/<driver>/<name>.<ext>
  group/<server>/<driver>/<group>/<name>.<ext>
  connection/<server>/<driver>/<group>/<conn>/<name>.<ext>
<
The file extension is taken from the source buffer (e.g. `.sql`, `.cypher`).
Files can be opened, edited, and deleted directly in the filesystem.
The directory is created automatically on first save. Override the location
with |grannos-queries_dir|.

EXPLORER                                                    *grannos-explorer*

|:DbExplore| opens a vertical sidebar showing the database object tree.
The window title bar (winbar) displays the connection name and driver.
The buffer is named `grannos://explorer [name (driver)]`.

KEYMAPS ~

  <CR>    Expand or collapse a node. Does nothing on non-expandable nodes.

  K       Describe the item under the cursor: fetches metadata from the
          server (column types, index fields, etc.) and displays it in a
          floating window. Press q or <Esc> to close.

          Inside a table's describe float, K on a row of the column table
          opens that column's own detail float on top — defaults, indices,
          foreign keys, and sample values. Press q or <Esc> to close it and
          return to the table.

  R       Refresh the entire tree from the server, bypassing the
          server-side schema cache.

  g?      Show a keymap reference float.

TREE STRUCTURE ~

The tree hierarchy is entirely defined by the server. Refer to your
server's documentation for the object tree it exposes per driver.

RESULTS WINDOW                                               *grannos-results*

Query results are shown in a dedicated buffer named `grannos://results`.

- Columns are right-padded and aligned.
- A separator line is drawn below the header.
- A row count is shown at the bottom.
- DML queries (INSERT, UPDATE, DELETE) show an affected-row count instead.
- Multiple statements separated by `;` are executed sequentially; each
  result is shown under a labelled heading (`── Query 1 / 3 ──`, etc.).
- Results are paginated; page size is controlled by |grannos-page_size|.

The buffer is read-only and reused across queries. Its direction and size
are controlled by |grannos-results-split| and |grannos-results-height|.

STATEMENT MESSAGES ~
                                                    *grannos-messages*

Some statements produce text alongside their result — Oracle
`DBMS_OUTPUT.PUT_LINE` output, or the compilation errors of a PL/SQL object
that Oracle "created" successfully but which does not compile. These are
shown just above the result table, one line each:

    2 rows  ·  0.003s
                                                                        ~
    › starting
    ⚠ 3:5  PLS-00201: identifier 'NO_SUCH_THING' must be declared
                                                                        ~
    │ ID │ NAME  │
    ├────┼───────┤

A message is not an error — the statement succeeded. Failures still replace
the whole result with an `Error:` message as before.

Two levels, each with its own highlight group:

  `›` info      Output the statement chose to emit.  `GrannosMessageInfo`
  `⚠` warning   The statement worked, but the server `GrannosMessageWarning`
              flagged a problem with it.

A warning that refers to a position in the query is prefixed with it as
`line:col` (or just `line` when the column is unknown), counted against the
query text exactly as you submitted it.

KEYMAPS ~

  H       Scroll left one column.
  L       Scroll right one column.
  c       Open a column picker to choose which columns to display.
  [       Go to the previous page of results.
  ]       Go to the next page of results.
  q       Close the results window.
  g?      Show a keymap reference float.

COMPLETION                                                *grannos-completion*

A SQL buffer associated with a connection gets 'omnifunc' set, so |i_CTRL-X_CTRL-O|
completes database names in place. No completion plugin is required; any
engine that wraps 'omnifunc' picks this up automatically.

What is offered depends on where the cursor sits:

  after FROM / JOIN / INTO / UPDATE
          Table and view names. Unqualified, schema names are offered too;
          after `schema.`, only that schema's tables.

  after `alias.` or `table.`
          The columns of whatever that qualifier binds to, resolved through
          the statement's FROM/JOIN clauses exactly as |grannos-hover-key|
          resolves it.

  anywhere a bare column resolves
          SELECT, WHERE, ON, GROUP BY, HAVING, ORDER BY, UPDATE ... SET, and
          an INSERT column list: the columns of every source in scope, each
          annotated with its type and the alias it came from, plus the
          aliases themselves.

Candidates are filtered by what has been typed, case-insensitively.

AS YOU TYPE (nvim-cmp) ~                              *grannos-completion-cmp*

'omnifunc' is manual. For a menu that opens while you type, grannos ships a
native nvim-cmp source named `grannos`: >lua
  require("cmp").setup({
    sources = { { name = "grannos" }, { name = "buffer" } },
  })
<
Or, to keep it to SQL buffers alone: >lua
  require("cmp").setup.filetype("sql", {
    sources = { { name = "grannos" }, { name = "buffer" } },
  })
<
The source registers itself from `require("grannos").setup()`. If cmp is
lazy-loaded it is not there yet at that point, so call this from cmp's own
config instead: >lua
  require("grannos.completion.cmp").setup()
<
The source is only active in a buffer that has a connection, and it triggers
on "." as well as on word characters — after `alias.` there is no word for cmp
to fire on, and that is where the column list matters most. Filtering is left
to cmp, so its own sorting and fuzzy matching apply.

Prefer a native source over `cmp-omni`: 'omnifunc' refreshes its own popup when
a listing arrives, which cmp neither sees nor honours, so a cold lookup through
`cmp-omni` shows an empty menu until the next keystroke. This source uses cmp's
`isIncomplete` instead and asks it to re-query when the answer lands.

Any other engine can drive 'omnifunc' directly; see |compl-omni|.

IMPACT ON THE DATABASE ~

Completion only ever sends `explore.list`, never `explore.describe`: it reads
the catalog and never user table data. Each listing is fetched once and cached
by the server permanently, so a database sees one catalog query per schema or
table actually completed against, and nothing at all thereafter — a whole
session of editing typically costs a handful of queries in total.

Nothing blocks on the network. A lookup that has not been fetched yet returns
what is already known and fills the popup in as the answer arrives.

Set |grannos-completion-enabled| to false to turn this off.

If |i_CTRL-X_CTRL-O| offers SQL keywords rather than your schema, the buffer
has no connection: 'omnifunc' is still Vim's own `sqlcomplete#Complete`. Check
with `:set omnifunc?` — an attached buffer reads
`v:lua.require'grannos.completion'.omnifunc`. Associate one with
|:DbAssociate| or |:DbAttach|.

require("grannos").cancel_query()

require("grannos").open_current_driver_help([{opts}])
    Fetch and display documentation for the driver associated with the

                                              *grannos.open_driver_help()*
require("grannos").open_driver_help({driver} [, {opts}])
    Fetch documentation for {driver} from the server and display it with

      position   "float" (default) — centered floating window.
                 "bottom"          — horizontal split at the bottom.

    Equivalent to pressing `?` in the connections panel (always float).

CONNECTIONS MODULE ~
                                                  *grannos-connections-api*

Connection keys are NUL-separated strings of the form
`server\0driver\0group\0name`. Most callers receive keys from other
module functions rather than constructing them directly.

require("grannos.connections").load_all()
    Returns the full file as a nested table:
    `{ server -> { driver -> { label, groups -> { group -> { name -> params } } } } }`

require("grannos.connections").load({server})
    Returns the driver map for {server}: `{ driver -> { label, groups -> ... } }`.

require("grannos.connections").get({key})
    Returns the params table for the 4-part {key}, or nil.

require("grannos.connections").delete({key})
    Removes the connection identified by {key} from the connections file.

require("grannos.connections").pick({caps}, {active_set}, {callback})
    Opens the connection picker. {active_set} is a table of currently
    connected keys (used to annotate entries). {caps} is the server
    capabilities object (used if the user selects "New connection").
    {callback} is called as `callback(key, params)` on selection, or
    `callback(nil)` on cancel.

require("grannos.connections").create({caps}, {callback})
    Runs the new-connection wizard using {caps} from the server to drive
    the driver list and field prompts. {callback} is called as
    `callback(key, params)` on completion, or `callback(nil)` on cancel.

require("grannos.connections").edit({key}, {caps}, {callback})
    Runs the edit wizard for the connection identified by {key}, with all
    fields pre-filled from the stored values. {callback} is called as
    `callback(new_key, params)` on completion, or `callback(nil)` on
    cancel.

require("grannos.connections").clone({key}, {new_name}, {caps}, {callback})
    Clones the connection identified by {key} as {new_name}, running the
    field-edit wizard with all values pre-filled. {callback} is called as
    `callback(new_key, params)` on completion, or `callback(nil)` on cancel.

require("grannos.connections").set_allow_writes({key})
    Sets `allow_writes = true` for the connection identified by {key} and
    persists the change to the connections file immediately. This suppresses
    all future write-protection prompts for that connection. See
    |grannos-write-protection|.

CONFIGURATION                                                 *grannos-config*

All keys are optional.

>lua
  require("grannos").setup({
    server_cmd       = "grannos",
    connections_file = nil,   -- auto-detected from $XDG_CONFIG_HOME
    queries_dir      = nil,   -- auto-detected from $XDG_DATA_HOME
    keymaps = {
      hover_key       = "K",
      query_info_key  = "gK",
      goto_symbol_key = "<C-]>",
    },
    results = {
      split               = "below",
      height              = 15,
      page_size           = 500,
      thousands_separator = "_",
      decimal_separator   = ".",
    },
    completion = {
      enabled         = true,
      max_schema_scan = 5,
    },
  })
<

                                                       *grannos-server_cmd*
server_cmd ~
  Type: `string`   Default: `"grannos"`

  Shell command used to launch the server process. Can include arguments.

                                                  *grannos-connections_file*
connections_file ~
  Type: `string`   Default: `$XDG_CONFIG_HOME/grannos/connections.json`

  Path to the JSON file where connections are stored. The directory is
  created automatically on first save.

                                              *grannos-completion-enabled*
completion.enabled ~
  Type: `boolean`   Default: `true`

  Set 'omnifunc' on SQL buffers that have a connection, so |i_CTRL-X_CTRL-O|
  completes table and column names. See |grannos-completion|. Set to false
  to leave 'omnifunc' alone.

                                      *grannos-completion-max_schema_scan*
completion.max_schema_scan ~
  Type: `number`   Default: `5`

  How many schemas may be listed to offer table names for a reference that
  names no schema. A connection with more schemas than this offers schema
  names alone, so completing an unqualified table position can never turn
  one keystroke into a listing per schema; writing `schema.` always lists
  just that one. Raise it for a database with many small schemas you query
  across; the cost is one catalog query per schema, once per session.

                                                      *grannos-queries_dir*
queries_dir ~
  Type: `string`   Default: `$XDG_DATA_HOME/grannos/queries`

  Root directory for saved queries. Each query is stored as a plain text
  file in a subdirectory that encodes its scope. The directory is created
  automatically on first save. See |grannos-saved-queries|.

                                                    *grannos-hover-key*
keymaps.hover_key ~
  Type: `string`   Default: `"K"`

  Key that describes the item under the cursor. In the connections panel it
  opens the hover float (connection details or error message); in the
  explorer, the results pane and a query buffer it describes the symbol
  under the cursor.

                                               *grannos-query-info-key*
keymaps.query_info_key ~
  Type: `string`   Default: `"gK"`

  Key inside a query buffer that shows execution info (time, duration, row
  counts, error) for the statement under the cursor. Unlike |grannos-hover-key|
  it is statement-scoped, so it works from any column of the statement,
  identifiers included. Press it again while the float is open to reopen
  that statement's results in the results pane.

                                              *grannos-goto-symbol-key*
keymaps.goto_symbol_key ~
  Type: `string`   Default: `"<C-]>"`

  Key inside a query buffer that reveals the symbol under the cursor in the
  schema explorer: the sidebar opens (or is focused) for the buffer's
  connection, the tree expands down to the node, and the cursor lands on it.
  The symbol is resolved exactly as |grannos-hover-key| resolves it; when it
  matches several nodes a |vim.ui.select()| prompt asks which one to jump to.

                                                   *grannos-results-split*
results.split ~
  Type: `"below"` | `"right"`   Default: `"below"`

  Direction of the results window split.

                                                  *grannos-results-height*
results.height ~
  Type: `integer`   Default: `15`

  Height in lines of the results split (only applies when `split = "below"`).

                                                       *grannos-page_size*
results.page_size ~
  Type: `integer`   Default: `500`

  Number of rows per page in the results window. Use `[` and `]` to
  navigate between pages.

                                              *grannos-thousands_separator*
results.thousands_separator ~
  Type: `string|false`   Default: `"_"`

  Character inserted between digit groups in numeric cells (e.g.
  `"1_234_567"`). Set to `false` or `""` to disable grouping.

                                                *grannos-decimal_separator*
results.decimal_separator ~
  Type: `string|false`   Default: `"."`

  Character used as the decimal point in numeric cells (e.g. `"1234.56"`).
  Set to `false` or `""` to display numbers with a literal `.` decimal point
  instead (equivalent to the default). For European-style numbers, set
  `thousands_separator = "."` and `decimal_separator = ","` (e.g.
  `"1.234.567,89"`).

  The thousands separator is highlighted slightly dimmer than the digits
  (`GrannosThousandsSeparator`); the decimal separator is always
  highlighted the same as the surrounding digits.

SUPPORTED DATABASES                                          *grannos-drivers*

The available drivers depend entirely on the server. Driver identifiers and
their connection parameters are announced at runtime via the `capabilities`
protocol method — the plugin uses this response to populate the connection
wizard and does not hard-code any driver list.

Refer to your server's documentation for the drivers it supports.

For the protocol specification (wire format and methods) see
docs/protocol.md.

HEALTH CHECK                                                  *grannos-health*

Run |:checkhealth| grannos to verify the installation. It reports on:

REQUIREMENTS ~
    The running Neovim is 0.9 or later.

CONFIGURATION ~
    `require("grannos").setup()` has been called, where the connections
    file and the queries directory resolve to, and whether the connections
    file (if it exists) is valid JSON.

BACKEND ~
    The executable named by |grannos-server_cmd| exists and is runnable.
    A short-lived server process is then started and asked for
    `capabilities`; the check reports the server name it answers with, its
    protocol version against the one this client expects, and the drivers
    it makes available. A server that fails to start is reported with its
    exit code and whatever it wrote to stderr, which is usually enough to
    tell a missing install from a broken one.

    This probe runs its own process and does not touch, or require, the
    server started by |:DbAttach|.

TREESITTER PARSERS ~
    The `sql`, `cypher`, `promql` and `json` parsers used to find the
    statement and the symbol under the cursor. The first three ship with
    this plugin; `json` (used for MongoDB queries) comes with Neovim.

OPTIONAL DEPENDENCIES ~
    Whether fzf-lua is installed for the saved-query picker; without it
    the picker falls back to `vim.ui.select`.
